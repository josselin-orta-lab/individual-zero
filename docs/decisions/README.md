# Architecture Decision Records

An ADR records a shared architectural decision after sufficient evidence or explicit constraints exist.

Use an ADR for changes such as a shared cognitive interface, the global execution cycle, structural relationships between several modules, a dependency that becomes part of the baseline, a shared benchmark definition that changes interpretation, or promotion of a new architectural generation.

Do not use an ADR for a local experiment choice, compatible refactor, minor dependency update, or ordinary bug fix.

An ADR never replaces an experiment.
