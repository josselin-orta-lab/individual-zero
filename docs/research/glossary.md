# Glossary

## ADR

**Architecture Decision Record.** A document recording a shared architectural decision after sufficient evidence or explicit constraints exist.

## Adapter

Code translating between an external component and the interfaces expected by I0.

## Baseline

The reference condition against which a variant is compared.

## Benchmark

A reusable scenario, dataset, metric, or comparison rule used across more than one experiment or variant.

## Candidate I(n+1)

An experimental architectural direction that may become a new reference generation if evidence becomes sufficient.

## EXP

A scientific experiment record preserving question, RAI, protocol, results, and decision.

## I0

The first integrated reference architecture of Individual Zero.

## I1, I2, ...

Later architectural generations. These are not ordinary software release numbers.

## Lab

Neutral infrastructure used to run, observe, measure, and reproduce research executions.

## RAI

**Reuse, Adapt, Implement.** A method for deciding whether to reuse an existing solution, adapt one, or implement a new mechanism.

## Reference behavior

The currently accepted behavior of an Individual generation used as a baseline for research.

## Research axis

A category used to map scientific questions. It does not define a source-code folder, team, or long-lived Git branch.

## Test

A software verification checking behavior against a known specification.

## Veto

A mechanism or condition able to prevent or interrupt a proposed action. Its exact implementation is a research question and should not be inferred from the term alone.
