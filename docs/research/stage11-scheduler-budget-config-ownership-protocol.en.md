`ComputeBudgetConfig` is a frozen dataclass, but its `module_envelopes` and `operation_costs` are caller-supplied mutable Mapping objects. `CycleComputeBudget.__init__` validates and then retains the same configuration object. A caller holding a dict can therefore replace a previously validated integer cost with zero (free operations), change a module envelope, or add a new vocabulary entry after owner initialization, without a change in `config_version`. The currently accepted operation-cost and boundary checks then consult the altered dict. This is a **producer reference aliasing defect**, not evidence of hostile Python code mutating private owner attributes or an observed real-world learning phenomenon.

## Frozen narrow correction

1. After validating `ComputeBudgetConfig` and before publishing a `CycleComputeBudget` owner, detach **both** mapping fields from the producer with fresh in-memory dicts containing the **exact same** already validated keys and integer values. Retain `version`, `cycle_ceiling`, `protected_modules`, `protected_capacity`, and `cycle_occurrence_guard` unchanged. No coercion, averaging, rounding, new cost or new implicit operation. The copy must occur even if the incoming Mapping is read-only (`MappingProxyType`).
2. The internal copy may use ordinary private dictionaries to preserve existing deterministic serialization/deepcopy expectations. No new public mutator is added; it is explicitly **not** a defense against hostile code given access to `owner._config`. Do not mutate caller mappings. Do not introduce a mappingproxy into fields that are serialized by `dataclasses.asdict` or copied by existing code without proving compatibility.
3. `quote_operations`, `charge`, `open_cycle`, `restore_causal_state`, P-43 costs/budgets, protected capacity, default/nondefault cycle occurrence guarding and existing snapshot schema remain byte-for-byte semantically unchanged for an unmodified valid config. Historical default journal hashes must not change.
4. The external `Stage4Config` / Stage-11 configuration may still hold references to caller dicts; this increment isolates the **Scheduler owner** only. Do not claim full immutability of the larger runtime's configuration graph.
5. A rejected invalid configuration remains rejected at validation; a valid owner subsequently remains valid even if the source dict is cleared, overwritten with noncanonical keys, or altered to an otherwise invalid cost. Re-restoring a compatible snapshot cannot borrow authority from new producer values.
