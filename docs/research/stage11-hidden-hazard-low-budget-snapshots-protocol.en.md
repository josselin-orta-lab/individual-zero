## World-only hazard input type fidelity addendum (2026-10-11, before implementation)

WorldBody's current scenario interface silently coerces `payload.active` using `bool(...)`; nonempty text such as `"false"` consequently activates a hazard. It also coerces grid coordinates through `int(...)` for danger/lethal-zone and creature inputs. These conversions change physical truth without matching the logged input's declared type and value. The external scenario interface MUST require `active` to be a literal Boolean for `set_danger_zone` and `set_lethal_zone` (default `True` when absent); any explicit non-Boolean is rejected. All world-only `position` inputs MUST contain exactly `x` and `y` as true integers (not bool, float or text), validated before mutation. This constraint is on **external world input interpretation**, not the individual's Action Control admissibility or spatial movement.

Fixed unit cases: `set_danger_zone` and `set_lethal_zone` reject `"false"`, `0`, `1`, `None` and array-typed activation; reject fractional, Boolean, string and extra-key grid positions. Preserve `world.export_causal_state()` exactly after each rejected call. Verify that a valid Boolean deactivation removes an actually active zone and that successful scenario programs still record receipt/application before Perception. No hidden world hazard is leaked to cognition.

## Hazard appearance and removal across successive steps (2026-10-11, before test implementation)

The fixed hidden-hazard test's initial `set_danger_zone(active=True)` is insufficient to exercise the reverse physical transition. Add a **public, versioned six-step software control** with two world-only events at the same coordinate `(3,2)`: step 3 `set_danger_zone(active=True)`, step 5 `set_danger_zone(active=False)`. Use the existing public junction, survey refresh, and two bounded UC profiles `(Planning, Exploration)=(0,0),(4,4)`. A control instance has the **same two schedule points** but both flags false. Compare the two instances' actual actions and local captures through step 2, before any physical change. At the end of step 4 only the hazard branch has an active danger zone; after step 5 both real worlds have no active zone. Both events MUST be journaled before application, with the original Boolean active values; no synthetic `known_lethal` fact is published from a benchmark label. Differing bodily consequences after step 3 may legitimately alter later cognition; no equality of later action histories is required.

Take a **full-owner periodic snapshot** at the end of step 4 and step 5 of the hazard branch, then advance to step 6 and restore each checkpoint in turn. Compare every exported causal owner exactly, including the external scenario cursor and the real WorldBody danger zones. The append-only technical journal is never rewound. Repeat an independent six-step run and compare full normalized journal bytes and owner states before any checkpoint restore. Do not assert that disappearance of a real danger is automatically recognized by the individual, and do not conflate a world-only input with learned safety knowledge.

A failed test is preserved and diagnosed, not weakened into a misleading success.
