# A2-R — porte d'admission d'un contexte de run, sans lancement (30 octobre 2026)

**Tranche strictement technique de préflight.** Le protocole prospectif A2-R reste préenregistré : deux fonctions de récompense, 24 graines indépendantes, deux rôles contrebalancés, 96 vies H192. Ni le moteur I1/I0, ni les récompenses, ni les seuils ni les critères scientifiques ne changent.

`tools/i1_eco_a2r_launch_gate.py` refuse un contexte dont le couple (rôle, graine, mode) sort de la matrice gelée ; un verrou d'origine dont les octets ou le SHA-256 externe ne concordent pas ; un lock JSON non canonique ; un HEAD source, arbre source, preset ou run ID incohérent ; un événement différent d'un `workflow_dispatch` initial, une tentative de relance, une branche autre que `main`, un workflow autre que l'identifiant réservé ; ou une attestation de revue qui ne référence pas exactement le protocole, le lock et le run.

Le module renvoie une **vérification de cohérence de déclarations**, **jamais une autorisation d'exécuter une vie**. Variables d'environnement, lock et marqueur de revue peuvent être falsifiés hors d'une infrastructure GitHub protégée. Le workflow de cohorte `i1-a2r-confirmatory-one-shot.yml` n'existe pas à ce stade : son nom est réservé afin de rendre impossible une activation accidentelle ; aucun runner de vie, dispatch, schedule, ou commande A2-R 96 vies n'est ajouté ici. Il faudra attester indépendamment le vrai SHA / run GitHub / tentative, geler et publier le lock externe, protéger l'approbation scientifique et implémenter un lanceur qui préserve chaque échec de naissance et les octets originaux. Tant qu'une seule de ces portes manque, **STOP / NOT_AUTHORIZED**.

Les tests négatifs purs vérifient les faux SHA, retries, branches, workflows, identités, tentatives et revues ; la CI existante est étendue, sans CI générale lourde, sur Python 3.11/3.12. Résultats H48 précédents uniquement exploratoires ; **A1-C NO_GO, A2-R NOT_EXECUTED (0/96), L3 NOT_ESTABLISHED**.
