## New prospective test matrix, fixed before observing outcomes

- Build two **controlled exploration-coefficient variants**, not full different birth temperaments: duplicate the exact public `build_stage11_reference_runtime(enable_geography=True)` world, safety facts, WorldBody, Equipment and all nested stage4–9 config parameters. Only `Stage11Config.temperament_parameters.exploration_coefficient` differs: **A = -1.0**, **B = +1.0**. Append separate descriptive version strings to `Stage11Config` so their journals are not falsely compared as one identical run.
- Use a physically satisfied starting body `energy=50,food=60,water=60,integrity=100` at the fixture's same position/layout. Run exactly **5 world steps** under the original P-43 costs/envelopes and the existing Action Control/Planning pipeline. No oracle access from the individual, no injected scenario, no external state modification during steps.
- Predefine measurable outputs: `CompetitionConfig.gain`, raw derived coefficient, candidate motivational fields in any existing `stage11_intrinsic_evaluation` events, real movement commands with `option:geographic:` identifiers, physical positions `perceptual_capture`, number of distinct actually captured geographical sites, total charged UC, source/owner version and final journal hashes. Use the *same input and snapshot schedule* for two independent runs of **each** variant.
- The invariant gate is strict: both variants' `CompetitionConfig.gain` and all configured P-43 costs must remain identical; a derived exploration coefficient may change `m_a`, option outcomes and visited positions, **not** `g`. At high coefficient B there should be some grounded intrinsic geographic motivation and at least one genuinely executed exploration movement toward the observed northern frontier; if missing, report failure and investigate rather than adjusting parameters. At low coefficient A no positive `m_a` is allowed for informational options; do not require the two different configurations' journal hashes to match.
- Repeat two independent runs for each variant; compare complete journal canonical bytes and final causal owner states **within the same version**, with snapshots captured at the end of physical step 4 in the same place in the timeline and restored in the same fixed order only if included in both independent runs. No post-hoc extension of the horizon to force a movement; a negative result remains valid.
- This is a coefficient-isolation *software ablation*, not a complete A/B temperament genotype proof: it does **not** claim to re-project every Gatekeeper, Value-Needs or Stage-5 parameter from birth when only `exploration_coefficient` is varied. The rest of the temperament vector stays fixed deliberately.
- Execute and preserve tests on SHA, then Python 3.11/3.12 full CI and technical reference artifacts; count failures and skips honestly. No merge, specification edit or frozen Golden rewrite.
