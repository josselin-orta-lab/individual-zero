# Individual `I<n>`: independent-generation review template

**Status:** TEMPLATE_ONLY. This is a checklist for a *proposed* new generation, never an active engine, born individual, runtime contract or scientific verdict. Replace `I<n>` with a proposed identifier only after reviewing [ADR-0001](../decisions/ADR-0001-strict-generation-autonomy.md) and the [engine promotion procedure](../engineering/ENGINE_PROMOTION.md).

## Identity and activation
- **Generation / parent lineage / target commit:** declare exact refs. Parent is historical comparison, never a runtime import or transferable living state.
- **Registry state:** NOT_REGISTERED, unless explicit independent registration has been authorized and verified.
- **Executable entrypoints / birth permission:** NONE until technical, architectural and scientific gates authorize them.
- **Change owner and review authority:** issue, ADR, experimental preregistration and independent reviewer.

## Research objective and falsification
Describe the specific limitation in the current generation, the incompatible architectural requirement, competing hypotheses, control, negative result criteria and evidence needed before promotion. A successful unit test does not establish a natural, efficient or autonomous learner.

## Owned technical boundaries
| Required domain | Generation-owned implementation and evidence | Status |
| --- | --- | --- |
| Cognitive modules, input provenance, source ownership | source paths, contracts and tests | NOT_EVALUATED |
| Physical WorldBody and first-person observation | isolated environment and provenance | NOT_EVALUATED |
| UC Scheduler and charged computation | real budget records, rejection tests | NOT_EVALUATED |
| Competition, Action Control and motor admission | veto, stale-input and safety tests | NOT_EVALUATED |
| Identity, mortality and authenticated M11 | one owner roster, terminal seal, cold recovery, crash/rollback refusal | NOT_EVALUATED |
| Independent scientific protocol and comparator | preregistered data, held-out controls, exact SHA, uncertainty | NOT_EVALUATED |

## Validation and decision gates
Separate (1) **static structure**, (2) **software tests on an exact commit**, (3) **observed lived behavior**, and (4) **scientific evidence with an explicit reviewed verdict**. Record PASS / FAIL / NOT_RUN / NOT_ESTABLISHED without substitution. Enumerate forbidden claims, incomplete implementations and adversarial counterexamples.

## Repository and agent handoff
Provide generation-owned `src/iN/engine.json`, `src/iN/AGENTS.md`, `src/iN/docs/README.md` and `STATUS.md`, plus explicit test vectors and the authoritative issue/ADR. Do **not** reuse an obsolete engine's Lab, memory, cognition, Scheduler, M11, birth state or compatibility fallback. A prototype's synthetic ports confer no real motor or recovery authority.

**Promotion is an independent review and approval decision**, not a filename, copy operation, successful test or automatic lineage upgrade.
