## Fixed question and exposures

Can P1.3 FIXED and the current physically funded GATE both execute as a pair on genuinely constructed new-F0-family worlds, with valid physical cognitive accounting, exact paired identity and a sealed no-retry original G/R transport?

The study uses the **first 96 units**, in the existing deterministic order, of the **PUBLIC SYNTHETIC** 1,500-pair preview. It never searches for a convenient seed, a survivable world, a favorable GATE life or a quieter computational budget. The pair outcomes are never accessed to decide unit inclusion. Its 96 world seeds, 96 newborn G0 genome seeds, 96 life seeds and family draws are exactly those of the existing preview, and its full schedule can be regenerated before any test. Both arms of each pair share one initial WorldSpec, one newborn genome and one life seed, with arm order fixed to FIXED then GATE. No WorldSpec is counted as an independent scientific replication.

There are **192 full-policy engineering lives**, each with an upper horizon of 400 steps (76,800 maximum world steps), across the previously declared F0 stable, depletion and pulse families. The exact source is fingerprinted from all I3 module, runtime and lab Python files. A fresh **engineering** ticket binds each GATE life to its own WorldSpec SHA-256, declared family, world seed, pair index, source fingerprint and policy. This is **not** a science admission, and the existing historical DEVELOPMENT 80/81 transport remains hard-closed.

## Execution and custody

```bash
PYTHONPATH=src python -m i3.lab.stage2_survival_b1_engineering rehearse
```

This runs the existing `two_phase_panel.sealed_rehearsal` in a temporary directory. Phase G executes each funded life and writes a deterministic gzip original immediately; an error stops generation, retains a structural fail-closed receipt and never counts as a death. Phase R revalidates packed/unpacked SHA-256s and identities and reduces all originals only after complete Phase G. A failed stage never becomes a favorable partial result. Every source, admission and accounting invariant must hold. **All engineering original life records are temporary and destroyed after G/R.**

Only the structural report may leave CI: status, counts, failure type, manifest digest, source fingerprint, mean computation ms/step, invariant failures and negative science flags. Mortality, life duration, actions, choices, internal memories, environmental resource locations, cognitive cost distributions and individual genomic outcomes are **not released or treated as survival evidence**.

The existing allowed `.github/workflows/i3-proposal-checks.yml` now provides an isolated B1 new-world job under the `research/i3-survival-b1-newworld-*` branch prefix, running the same 96-pair source and tests under Python 3.11 and 3.12. ## Scientific disposition

This 96-pair trial is not independent external sampling: its root key is PUBLIC and synthetic, it uses the first 96 predeclared preview rows, and it measures **engineering functionality**, not any inferential effect. A 96/96 paired PASS would mean the G/R transport and current source work on a nontrivial sample of new-F0 WorldSpecs, not that GATE survives better, that 1,500 pairs are adequately powered, or that the new WorldSpec process is causally independent of genomes.

**The actual scientific experiment remains awaiting** a justified survival-loss margin (or revised estimand that does not require one), robust independent sampling and exact paired test calibration, fully witnessed source/World/seed allocation, full-size exact-path engineering rehearsal, and separate prospective scoped authorization. The original 80/81 pilot cannot be replayed, the P2 reserve cannot be used and unregistered I3 is not promoted.

No user-provided delegation is misrepresented as an independent methodological sign-off. If this engineering trial fails, record the failure and determine whether it is a source/code defect or invalid World construction. Do not replace difficult worlds with favorable seeds or silently change the P1.3/GATE policy. Any repair is a new prospectively versioned source for future work.

**Decision after this attempt:** retain all negative or null engineering results, then prioritize prospective independent methodology and actual scientific cohort custody rather than adding new artificial survival rules.
