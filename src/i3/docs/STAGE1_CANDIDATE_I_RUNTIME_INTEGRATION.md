# Stage 1 Candidate-I: runnable multi-option integration gate

**PROSPECTIVELY FROZEN SOFTWARE GATE. NO FRESH DEVELOPMENT WORLD. NO LIVE
SCIENTIFIC EVIDENCE. NO ENGINE REGISTRATION.**

Baseline before protocol: `1c06ad80c1fed2919ddd5103b01c89f7de99bb83`.

This protocol follows:

- the shared first-contact prior capacity PASS (#1170);
- the Candidate-I I0-I9 integration PASS (#1174);
- the independent composite-funding reducer repair PASS (#1172).

Candidate-I is still a laboratory composition. This gate closes the remaining
gap between separate K80/P80/F108 software rows and a **single runnable
decision over the complete option set actually offered to one individual**.

## Why another software gate is required

I0-I9 established:

- the same paid inherited RMS/omega prior can be consumed on imagined and
  directly perceived first contact;
- an irrelevant first-contact state can fall back from the paid post-probe body
  to ordinary bodily-distress scoring with both legacy curiosity/prudence
  addends suppressed;
- post-contact Candidate-H semantics remain intact.

It did **not** establish how two or more unsupported resource actions compete
when they are offered in the same real decision, nor how an information-aware
RELEVANT score is handed to the existing Competition and ActionControl without
forcing an action.

No World may open until that composition is explicit and tested.

## Candidate-I runtime identity

The only new runnable policy name allowed by this protocol is:

`personal_shared_prior_candidate_i_v1`

It remains DEVELOPMENT-only and unregistered.

The runnable mind may be implemented as a new class/module. Historical
Candidate-H, Candidate-G and P1.3 classes must not be rewritten to acquire
Candidate-I behavior.

Persistent state remains:

- simulation mode: `reference`;
- projection accounting: `chunk_end`.

The genome's existing generic `omega` gene may be read **only during
unsupported first contact**. Post-contact must remain omega-free.

## Exact first-contact cases

### Imagined frontier first contact

The K80 semantics remain exactly #1170 / #1174:

- only the existing water-frontier opportunity representation is used;
- personal recurrence support is still required before the imagined
  future-opportunity kernel is actionable;
- the same paid RMS/omega effect prior is used;
- Candidate-H's strict imagined-first-contact relevance rule is unchanged;
- no food-frontier representation is invented here.

### Directly perceived unsupported resource actions

Start from the exact option set produced by the ordinary P1.3
perception/options path.

An **unsupported resource trial option** is an already offered option whose
first physical action is exactly one of:

- `("boire",)`;
- `("manger", internal_token)`;

and for which the individual's own EffectsModel has no personal exact-action
support.

Every such offered unsupported option must be treated symmetrically. No water
priority, food priority, token ordering, lexical ordering or first-seen winner
may affect whether it is evaluated.

For each unsupported resource option, Candidate-I uses the same
`paid_unknown_action_trial_value` structure as #1170, with the same paid
`paid_recent_rms_zero_mean_effect_prior` source and the genome's omega.

The post-trial subjective continuations remain the frozen minimal pair:

- STOP after the first trial;
- repeat the exact trial once.

No hidden World fact, action label coefficient or resource-specific innate
effect is allowed.

## Multi-option score geometry

When one or more unsupported perceived trials are present, the complete
decision is quoted before scoring.

All cells in the decision must use:

- the same post-probe forecast body;
- the same Candidate-F projection geometry for the information-aware matrix;
- one common work ceiling that covers all ordinary options and every
  unsupported trial branch.

For each unsupported trial option, retain separately:

- no-trial comparator value;
- trial-frozen value;
- trial-informed value;
- information value;
- trial advantage;
- shared-prior receipt.

For every ordinary/nontrial option, compute its Candidate-F score at the same
forecast body and projector.

### Generalized perceived relevance

The one-trial case must reduce exactly to frozen P80/F108.

For a multi-trial decision define:

- **with-information map**: ordinary Candidate-F scores plus each unsupported
  trial's `trial_informed_value`;
- **without-information map**: the same ordinary scores plus each unsupported
  trial's `trial_frozen_value`.

The perceived first-contact decision is RELEVANT iff:

1. the top set of the with-information map differs from the top set of the
   without-information map; and
2. at least one with-information top option is an unsupported trial with
   strictly positive information value.

This is the frozen minimal extension of #1170 to more than one trial. On the
single-trial P80/F108 fixtures it must classify state-for-state exactly as
#1170. If it does not, the implementation is a DEFECT; the rule must not be
retuned after seeing results.

## Final decision authority

### RELEVANT

A RELEVANT perceived-first-contact decision must **not force the trial action**.

The complete with-information score map is passed to the same Competition and
ActionControl semantics used by P1.3:

- same accumulator dynamics;
- same tie handling and RNG ownership;
- same motor admissibility;
- same innate integrity veto;
- if the highest-ranked option is rejected by control, subsequent ranked
  options are tried exactly as in P1.3.

To avoid duplicating or drifting control semantics, implementation may extract
a pure/shared finalization helper from `Mind`, but P1.3 decisions before and
after that refactor must remain exactly identical on frozen controls.

### FALLBACK

If first-contact information is not relevant, all Stage-A work remains paid.
From the post-probe body Candidate-I executes a complete ordinary Mind final
decision with:

`score_addend_mode="discard_both_bonus_terms"`

This is the frozen #1174 `P1.3_BASE_FINAL` route.

### PROBE_UNFUNDED

If the complete quoted probe/matrix cannot be physically funded, no Stage-B
decision is executed. Emit a complete composite funding receipt compatible
with the repaired reducer.

Statistical absence of enough personal RMS support is **not** physical
PROBE_UNFUNDED. It is a completed no-capacity first-contact probe and therefore
falls back to the paid base final decision.

## Post-contact

Once the exact action class has personal actionable support, Candidate-I uses
the #1163 Candidate-H post-contact path unchanged:

- no omega read;
- no shared inherited first-contact prior read;
- 68/12 POST80 classification must remain state-for-state identical;
- relevance remains actual decision-top effect;
- fallback semantics remain historical #1163 P1.3 fallback, not Candidate-I's
  first-contact addend-free fallback.

This protocol deliberately changes no post-contact rule.
