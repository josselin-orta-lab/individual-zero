## Hypothesis carried forward

The Candidate-G 80-state characterization showed a narrow but real capacity:

- one strictly advantageous epistemic trial out of 80 states;
- 27 explicit declines;
- personal recurrence probability only;
- P1.3 reference/chunk_end projection only;
- no omega.

The selected margin was small. Therefore this slice tests runtime composition
and physical cost before any new development allocation.

## Runtime policy

```text
reference_recurrence_frontier_information_v1
```

The class combines two already-tested reference-preserving substrates:

- `ReferenceOpportunityMemoryMind`: paid branch storage plus paid generic
  opportunity-onset recurrence storage;
- `ReferenceFrontierInformationMind`: P1.3 repertoire, Competition, Action
  Control and omega-free post-contact personal frontier information.

Candidate-F is not in the MRO and is not imported by this module.

Required architecture:

```text
simulation_mode       = reference
projection_accounting = chunk_end
omega                  = absent
```

No genome migration or new gene exists.

## First contact

Before any personal drink-effect sample exists, an offered frontier causes one
paid water-recurrence read for the decision.

### No recurrence support

Status:

```text
NO_PERSONAL_RECURRENCE_SUPPORT
```

No numeric substitute is created. Explorer options are scored by ordinary P1.3
reference projection with the old curiosity/relevance/prudence addends still
absent.

This is intentionally conservative and may leave a bootstrap problem. A
negative result is admissible.

### Recurrence support

The personal estimate supplies exactly:

```text
future_opportunity_probability_source =
    PAID_PERSONAL_ONSET_RECURRENCE
```

Each frontier explorer then uses the already-tested
`paid_water_one_future_opportunity_value` with:

- explicit personal recurrence probability;
- `omega=0`;
- current paid personal RMS effect scale;
- one common cumulative decision forecast ceiling.

The kernel's initial target-modality probability remains the existing
first-person map-based prior. Only the **future matching opportunity** is
replaced by personal recurrence.

## Post contact

After any personal drink-effect sample exists, Candidate-G stops treating the
drink effect as unsupported. It uses the existing omega-free personal frontier
path from `ReferenceFrontierInformationMind`.

The recurrence memory continues to be physically stored, but first-contact
recurrence estimation is not used in that post-contact decision.

## Cognitive custody

One cumulative forecast body includes:

1. decision preprocessing;
2. any already-paid recurrence or post-contact belief read;
3. every remaining option score;
4. full Competition ceiling.

Unsupported recurrence is not free: its negative read is paid.

Opportunity presence is captured from the individual's already perceived
first-person map and stored only through the inherited paid learning lifecycle.
No world time, absolute position or source identity enters recurrence.

## What remains unchanged

- P1.3 option repertoire;
- map/history and learned effects/TD values;
- Competition;
- Action Control;
- BodyLaws/tariffs;
- branch-memory capacity;
- opportunity-memory capacity;
- default reference policy.

Old additive curiosity/relevance/prudence terms are not applied to Candidate-G
scores.

## Gate to any new world

This software integration is not enough to open a study.

Before a fresh development allocation, require:

1. full dual-Python software CI;
2. observer authentication of recurrence source and score decomposition;
3. a deterministic cost profile showing the supported-recurrence path is
   actually fundable on representative software states;
4. no hidden omega/Candidate-F dependency;
5. a prospectively frozen development question.

If the runtime path is computationally unaffordable or recurrence almost never
gets support, stop before opening another world.
