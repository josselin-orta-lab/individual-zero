## Precise missing trust boundary

The loopback remote CAS process in `engineering_remote_authority.py` writes a hash-chained SQLite authority ledger, but **both the authority DB and its audit chain can be rolled back together**. Its hash chain is not an external monotonic anchor. Client-signed HMAC is a transport/channel credential, not independent anti-rollback attestation. Existing tests prove common rollback of both **local** I3 files only when the remote server retains newer state; they do NOT demonstrate service-store rollback detection.

This work introduces **a minimal, optional external-anchor interface** in `RemoteEngineeringWitness` with a fail-closed committed-state invariant. It does not implement, invent or provision an actual independent anchor service, secret key, host, or signer; tests use a volatile separate test object explicitly NOT equivalent to production M11. It does not promote I3.

## Intervention contract frozen before implementation

- Constructor opt-in `commit_anchor`, default `None` for existing engineering fixtures. If present it must have callable `assert_current(remote_committed_receipt)` and `publish(remote_committed_receipt)`; no exceptions swallowed. No API to reset, replace, silently ignore or decrement a pin.
- After a cryptographically verified remote `register` response that matches original local genesis, invoke `publish` before reporting registration succeeded. After a cryptographically verified `commit` response that matches the actually sealed local POST_PAID_LEARNING event, invoke `publish` before reporting completion. If the optional independent anchor rejects or is unavailable, the active process stops, without reissuing a motor. Underlying transaction can already have committed; never presume rollback because acknowledgement failed.
- During `verify` (which is called before any new native motor), authenticate and compare original remote state with original local ledger, and then call `assert_current`. A stale server state with a rolled-back local ledger must fail if an independently preserved higher pin was supplied. Also call `assert_current` before sending `prepare` to reject any stale local pinned committed receipt even if the client mistakenly omits the standard previous verification. Preserve pre-World PREPARED requirements. External pin never chooses action or gains access to hidden World or the genome.
- Test anchor is a strict stateful in-memory implementation retained while *both* local databases and the server SQLite authority database are deliberately rolled back; expected result is rejection before a new native World.step. Also test normal 2-step externally pinned CAS, failure of anchor after actual server commit, no accidental state recovery of an uncertain transaction, and that default `commit_anchor=None` still cannot claim independence.
- No cryptographic claim from an in-memory test pin; the real release gap is a **third independent protected trust domain** with operator attestation/credential rotation, off-host durable monotonic state and signed replay-proof provenance. No production M11 PASS until separately deployed/tested; `independent_m11_antirollback=False` remains unchanged in existing native receipts.
- Follow exact-source Python 3.11/3.12 I3 CI. Tests cannot be counted as scientific world births; every engineering-only native World, if used, is a synthetic local TEST and no original cohort is opened.

**Falsifiers/STOP:** a stale remote state is accepted under a retained higher pin; a `publish` or `assert_current` exception is swallowed; any World.step occurs after a failed pre-motor anchor check; a replayed PREPARED motor is retried; an unpinned default becomes described as externally anchored. On failure preserve original working authority code and do not broaden risk assumptions.
